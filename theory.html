Gradient Descent: Pricing Houses in Pune

Aim Theory Procedure Simulation Contributors

Theory

1. The model

For a house of x sq ft, we predict the price (in ₹ lakh) as:

ŷ = w · x + b

w is the price added per extra sq ft. b is the base price when area is zero. Learning means finding the best w and b.

2. The cost: how wrong are we?

For each house, the error is predicted minus actual price. Squaring and averaging gives one number to minimise:

J(w, b) = (1 / 2n) · Σ ( ŷᵢ − yᵢ )²

Plotted against w and b, J forms a bowl. The simulation draws it as a contour map: darker means more error, and the lowest point is the best line.

3. The gradient: which way is downhill?

∂J/∂w = (1/n) Σ ( ŷᵢ − yᵢ ) · xᵢ     ∂J/∂b = (1/n) Σ ( ŷᵢ − yᵢ )

If the model underprices most houses, the errors are negative and the gradient says "raise the prices". Larger houses count more in ∂J/∂w because they are multiplied by x.

4. The update rule

w ← w − α · ∂J/∂w     b ← b − α · ∂J/∂b

α is the learning rate, the size of each step. Repeat until J stops falling.

Worked example (3 houses)

Take areas in hundreds of sq ft: (10, ₹50 L), (15, ₹70 L), (20, ₹95 L). Start at w = 0, b = 0 with α = 0.01.

QuantityValue
Predictions0, 0, 0
Errors (ŷ − y)−50, −70, −95
∂J/∂w(−500 − 1050 − 1900) / 3 = −1150
∂J/∂b(−215) / 3 ≈ −71.7
New w, b0.01 × 1150 = 11.5, and b ≈ 0.72

Check the new prediction for the 1,000 sq ft house: 11.5 × 10 + 0.72 ≈ ₹116 L against an actual ₹50 L. We overshot. The step was too big for unscaled areas, which leads to the next two ideas.

Learning rate

Too small: training crawls. Too large: each step jumps over the minimum and the error grows (divergence). Somewhere in between, the error falls smoothly.

Feature scaling

Areas run into the thousands while the base price is a small number, so the bowl becomes a long narrow valley. One learning rate cannot suit both directions: either w zigzags or b crawls. Standardising area as (x − mean) / std makes the bowl round, so a single α works well for both.

Batch, stochastic, mini-batch

  • Batch uses all 40 houses per step: smooth, steady path.
  • Stochastic (SGD) uses 1 random house per step: cheap but noisy, and it jitters around the minimum.
  • Mini-batch uses a handful (8 here): a compromise, and the usual choice in practice.
